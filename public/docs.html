socketsubDocs

Client protocol

socketsub watches RSS and Atom feeds for you. You open a WebSocket, send the feed URLs you care about, and receive a message each time one of them changes. socketsub finds each feed's rssCloud or WebSub support and handles the subscriptions.

Connect

Open a WebSocket to:

{{wsUrl}}

All messages in both directions are JSON text frames. Feeds belong to the connection: when it closes, socketsub forgets them. After a reconnect, subscribe to your feeds again.

Send messages

Every message you send is a JSON object with a type and a urls array of feed URL strings.

subscribe

{
  "type": "subscribe",
  "urls": ["https://example.com/feed.xml", "https://blog.example/atom"]
}
  • Each subscribe adds to the feeds this connection already follows. Subscribing to a URL again is harmless.
  • Use the feed's URL, not the URL of a web page. Only http and https URLs are accepted.

unsubscribe

{
  "type": "unsubscribe",
  "urls": ["https://example.com/feed.xml"]
}
  • Each URL gets a status with state unsubscribed, even if this connection never followed it.
  • Closing the connection unsubscribes from everything.

Receive messages

The server sends three kinds of message. Every url field is the exact string you sent, even if the feed redirects or has a different canonical URL, so you can use it as a key.

status

Sent once for each URL you subscribe to, again each time that feed's state changes, and once for each URL you unsubscribe from. 

{
  "type": "status",
  "url": "https://example.com/feed.xml",
  "state": "subscribed",
  "via": "rsscloud"
}
Field Meaning
state One of the states in the next table.
via rsscloud or websub. Present once socketsub has picked a protocol for the feed.
detail A human-readable reason. Present on error and unsupported, and on pending when rssCloud failed and WebSub is being tried.

States:

State Meaning
pending socketsub is fetching the feed or waiting for the rssCloud server or WebSub hub to confirm.
subscribed You will get update messages for this feed.
unsupported The feed advertises neither rssCloud nor WebSub. You will not get updates for it.
error The URL was invalid, a limit was reached, the feed could not be fetched, or the subscription failed. See detail. You will not get updates for it.
unsubscribed Your unsubscribe went through. You will not get updates for it.

update

Sent each time the feed's publisher reports a change. Fetch the feed yourself to get the new content. 

{ "type": "update", "url": "https://example.com/feed.xml" }

error

Sent when a whole message is rejected: it is not JSON, has no valid type, its urls is not an array of strings, or it has too many URLs. Problems with a single URL come back as a status with state error instead. 

{ "type": "error", "message": "message is not valid JSON" }

Example session

> {"type":"subscribe","urls":["http://scripting.com/rss.xml","https://xkcd.com/rss.xml"]}
< {"type":"status","url":"http://scripting.com/rss.xml","state":"pending"}
< {"type":"status","url":"https://xkcd.com/rss.xml","state":"pending"}
< {"type":"status","url":"https://xkcd.com/rss.xml","state":"unsupported","detail":"feed advertises neither rssCloud nor WebSub"}
< {"type":"status","url":"http://scripting.com/rss.xml","state":"pending","via":"rsscloud"}
< {"type":"status","url":"http://scripting.com/rss.xml","state":"subscribed","via":"rsscloud"}
...
< {"type":"update","url":"http://scripting.com/rss.xml"}
> {"type":"unsubscribe","urls":["http://scripting.com/rss.xml"]}
< {"type":"status","url":"http://scripting.com/rss.xml","state":"unsubscribed"}

Example client

const feeds = ['http://scripting.com/rss.xml'];
const socket = new WebSocket('{{wsUrl}}');

socket.addEventListener('open', () => {
    socket.send(JSON.stringify({ type: 'subscribe', urls: feeds }));
});

socket.addEventListener('message', event => {
    const message = JSON.parse(event.data);
    if (message.type === 'update') {
        console.log('changed:', message.url);
    } else if (message.type === 'status') {
        console.log(message.url, message.state, message.detail ?? '');
    } else {
        console.error(message.message);
    }
});

Limits

URLs in one message {{maxFeedsPerMessage}}
Feeds per connection {{maxFeedsPerClient}}
Feeds across the server {{maxFeeds}}
Message size 1 MiB. Larger messages close the connection with code 1009.

Feeds on private or loopback addresses are refused.
